# Browser tool limits audit

`browser_upload` stages ordinary uploads from open regular-file descriptors in 1 MiB chunks. The default file and total limits are now `Number.MAX_SAFE_INTEGER`; `uploadMaxFileBytes` and `uploadMaxTotalBytes` can impose lower limits. Uploads accept any positive number of explicit paths. The default deadline is five minutes and the maximum is 2,147,483,647 ms, the platform timer limit. Explicit MIME overrides still use Playwright's in-memory payload API, which rejects payloads of 52,428,800 bytes or more. Omit overrides for large files; Chromium determines their MIME types from filenames.

Staging uses disk space proportional to the selected files, retained until verified browser closure because Chromium can read them later. Playwright may create another temporary copy. Upload results expose the private staging path and its retained status once file dispatch starts; failed or unverified browser closure reports the retained paths when available. Never delete them until the browser is known to have stopped using them. A crash can leave private `pi-browser-upload-*` directories under the OS temporary directory without a recorded result; inspect ownership and browser process state before manual recovery. There is no automatic orphan cleanup. Disk exhaustion or filesystem quota errors are reported when the filesystem returns them; free-space checks cannot guarantee later writes. Staging checks size and modification time before and after copying, but concurrent same-size changes with restored timestamps are not detectable and may produce mixed content. The opened descriptor prevents final-component symlink substitution, but parent symlinks are followed. Applications may impose independent upload limits.

`browser_download` streams completed native downloads into private artifacts. `downloadMaxFileBytes`, `downloadMaxActive`, and `artifactQuotaBytes` default to `Number.MAX_SAFE_INTEGER` and accept lower configured limits. Download history is retained in process without a small default count cap; large lists are returned as owner-scoped artifacts. Artifacts expire after the configured TTL, which begins on publication. Chromium may also hold a complete temporary copy, so disk usage can exceed the artifact size. Large or concurrent captures can exhaust disk, file descriptors, and memory. Capture waits without a fixed overall transfer deadline; cancellation remains available. Artifact publication and reads are serialized under a filesystem lock. Calls with an abort signal can cancel while waiting; a crashed lock requires manual inspection and can block them indefinitely. A crash may leave private partial artifact files that are retained and counted against the quota. If artifact publication fails after a native download completed, the tool retains the native bytes while the browser session is open and reports `nativeRecovery: available_until_session_close`. Use `browser_download` action `export_native` with the download ID and an absolute, nonexistent destination to copy them; no existing file is overwritten, but a failed or cancelled export can leave a partial file. Parent-directory symlinks are followed. Explicit `browser_session` stop blocks when it observes active downloads or unexported retained native bytes. Wait or export first, or set `abandonDownloads=true` to accept possible loss. Visible restart checks the same risk before requesting consent and again immediately before closing; tab close also refuses while that risk exists. These pre-close checks are not atomic browser download fences: a page can initiate another download as closure begins. Browser shutdown and forced closures cannot wait indefinitely; they can destroy native bytes and change their status to `unknown_after_close`. Shutdown reports known owner-scoped risks, but unexpected process failure can prevent that report. Completed artifact IDs remain visible in the owner's closed-session download list until artifact expiry, while the extension runtime remains alive. After reload, `browser_artifact` action `list` discovers the same Pi owner's unexpired artifact IDs, sizes and kinds using `nextAfterId` pagination; the durable store does not retain download names or source browser session IDs, and the native recovery/download record index does not survive reload. Pagination is not a snapshot, so additions before the cursor can be missed.

Other limits remain, and are not claims about websites:

- Snapshot defaults are 2,000 nodes per frame, 100 records, 12,000 UTF-8 JSON bytes and 32 frames. Callers can raise these budgets to positive safe integers; omission is reported. Large requests can exhaust browser or host memory. Reference-identity and complex selector budgets are also configurable and remain fail-closed; see `snapshot-extraction-budgets.md`.
- Extraction defaults are 4,000 nodes, 256 Ki UTF-16 code units, 128 levels and 8,192 metadata characters. Callers can raise these and the derived heading/link budget to positive safe integers. Extraction fails rather than returning an apparently complete partial record; DOM/eval provides explicit alternative access. Artifact quotas and platform limits still apply.
- Picker multi-selection defaults to 20; callers can request any positive safe integer. Retained handles and output grow with the number selected and can exhaust browser or host memory. Per-element summaries remain bounded and report truncation and omissions. Large batches retain all per-element metadata in a private owner-scoped artifact; quota or publication failure is reported after selection completes and handles are disposed.
- Action values have no tool-specific length limit. Large values can exhaust browser or host memory, exceed platform transport limits, or run past action deadlines.
- Screenshot dimension, pixel and PNG-byte budgets retain defaults of 8,192 px, 16 million pixels and 12 million bytes, and can be raised to safe integers. Larger values may be rejected by Chromium or exhaust browser, host or client memory; preflight cannot strictly bound native capture or transient PNG/base64 allocation. Large images consume artifact quota and are returned directly as base64 unless that would exceed Node's string limit or conversion throws a recoverable error. In either case the response reports image omission and provides the saved artifact. A fatal out-of-memory termination cannot return that response. Artifact retrieval uses bounded chunks. Diagnostic capture/history uses bounded retention and reports omissions or saturation.
- Recording duration defaults to five minutes and can be configured up to 2,147,483,647 ms, the Node timer maximum. Video recording has no fixed page count and recording history has no small entry cap; more pages and longer recordings consume native disk space and host memory. Video session startup warns that the deadline closes the browser even with active or unexported native downloads. At deadline, the owner-scoped video record reports observed download risks and unknown availability after closure; an owner UI warning is attempted when available. Downloads starting during closure may not be observed. Finalization still has a configured shutdown deadline and can report unknown while background work continues. Recovery scans have no fixed 10,000-entry ceiling, accept cancellable offset pages and configurable page size, and report further pages; each page rescans the temporary directory and concurrent changes can shift results. Large recovery or video-status pages use owner-scoped artifacts.
- Managed navigation, snapshot/action/chooser selectors, role names, dialog prompt input and eval code have no tool-specific length maximum. Long inputs consume browser and host memory and can exceed platform limits. Oversized action and dialog-operation results use owner-scoped artifacts while preserving dispatch status and verification in the response; if artifact publication fails, those fields and an explicit unsaved-result warning remain available. Action, snapshot-ref click, upload, managed navigation, attachment, download wait, and screenshot/viewport deadlines retain their defaults and accept up to 2,147,483,647 ms, the Node/Playwright timer maximum; larger timer values can fire immediately in Node. Dialog message and default-value previews report whether they were truncated. Session/attachment admission and response-body retention have independent caps.
